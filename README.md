# moli-2026 服务端

本仓库保存 CrossGate 服务端及其维护工具。

- `gmsv/`：服务端程序、GBK 控制台适配器、Lua 模块、NPC 脚本和静态地图/游戏数据。
- `tools/`：服务端内容整合、修复和验证工具。

客户端程序、图像、音效、客户端地图缓存、显示/语言工具，以及备份、日志、玩家数据库和运行存档不纳入版本控制。根目录采用白名单，避免后续 `git add .` 误加入客户端。

## 在新机器准备服务端

1. 将 `gmsv/setup.cf.example` 复制为 `gmsv/setup.cf`，填写数据库、GM 和服务间登录口令；模板保留原文件的 GBK 编码。
2. 将 `gmsv/data/debugger.txt.example` 复制为 `gmsv/data/debugger.txt`，按需要填写允许的 GM 账号。
3. SQLite 初始化结构在 `gmsv/sql/sqlite.sql`，仅包含表结构和服务端迁移版本记录，不含账号、角色、道具或宠物存档。仅在没有 `gmsv/data.db3` 的新环境中执行：

   ```powershell
   if (Test-Path gmsv/data.db3) { throw '数据库已存在，请保留现有数据。' }
   python -c "import sqlite3; from pathlib import Path; c=sqlite3.connect('gmsv/data.db3'); c.executescript(Path('gmsv/sql/sqlite.sql').read_text(encoding='utf-8')); c.close()"
   ```

   MySQL 的初始化脚本为 `gmsv/sql/mysql.sql`，切换数据库时同步修改 `setup.cf`。
4. 在 `gmsv` 下创建运行目录 `store`、`store/dungeon`、`store/house`、`store/itemcount`、`Dengon`、`dump`、`GMLog` 和 `house`。迁移已有服务器时，另行复制数据库和运行存档。
5. 从 `gmsv` 目录启动 `cgmsv-gbk.exe`；该适配器会启动同目录的 `cgmsv.exe`。

   ```powershell
   Set-Location gmsv
   .\cgmsv-gbk.exe
   ```

原有文件不转换编码或换行。服务端地图虽然是二进制文件，仍属于服务端必需的静态资源。

## 客户端连接与账号注册

1. 另行准备兼容的游戏客户端、资源及登录器；这些文件不包含在本仓库中。7.1 客户端资源对应关系见[宠物导入指南](docs/cg71_pet_import_guide_zh.md)。
2. 启动服务端后，将登录器的服务器地址指向本机 `127.0.0.1`；在其他电脑上连接时填写服务端所在电脑的地址。游戏端口以 `gmsv/setup.cf` 的 `port` 为准，模板为 `9030`。
3. 在服务端电脑打开[账号注册页面](http://127.0.0.1:10086/)，注册账号和密码，然后通过登录器进入游戏。HTTP 注册服务由 `http` 模块提供，当前监听端口为 `10086`。

默认加载的模块见 [ModuleConfig.lua](gmsv/lua/ModuleConfig.lua)。下列玩家命令来自已加载的 `gameQoL`、`fight`、`fivePet`、`skillLibrary`、`gameDifficulty` 和 `autoUnlock` 模块。`/help` 只显示当前已加载模块的命令。

### 自动加点

与自动加点师对话，先选人物或某只宠物，再选单项全加或自定义。输入的是**比例，不是固定点数**，顺序为**体力、力量、强度、速度、魔法**。例如 `1 2 0 1 0` 按 `1:2:0:1:0` 分配本次升级新增的点数；整数舍入进度跨等级累计保存。五项均为非负整数，合计必须在 1～100。

新角色、新宠物默认关闭，选定或保存方案后开启。原有剩余点数保留，不执行洗点；人物遵守单项等级上限，宠物种族自然成长照常计算。每只宠物按唯一编号保存方案，换栏位不会串配置，重登和重启后保留。详见[自动加点说明](docs/auto_stat/使用说明.md)。

### 宠物忠诚度

宠物忠诚度默认固定为 **100**，无需学习调教或输入命令。新获得与已有宠物在创建、属性重算、登录、战斗与保存时保持基础和实际忠诚度为 100；自动维护也会修正携带宠物，不受背包自动功能开关、战斗或摆摊限制。正常收宠仍可操作，宠物不会因忠诚度不足而发呆、乱行动或逃跑。

配置位于 `gmsv/cgmsv.cf`（`defaultloyalty=100`、`maxloyalty=100`）及 `gameQoL` 模块。正常保存角色并重启服务端后完整生效；运行中可先用 GM 命令 `/module reload gameQoL` 加载忠诚锁定逻辑，已有携带宠物将在自动维护时恢复到 100。

本引擎的宠物行为回调以 6 为正常分支：模块恢复回调传入的原始技能、目标与指令，并返回 6，避免额外发送“不听话”动画或改成普攻。返回 8 仍会发送不听话动画，不能用作正常分支；手动收宠分支保留。

### 单人五宠与技能配装

五宠模式**默认开启**。携带 1～5 只存活宠物，选定一只主宠，并离开其他玩家队伍后，会自动启动五宠小队，无需每次登录手动开启。**五只宠物固定在前排，人物在后排**；不足五只时同样固定宠物前排。人物和主宠由玩家操作，其余携带宠物每回合自动行动一次；跟随走路、跑步时静音。

到圣殿 **16,34** 的五宠指挥官处，分别选择其余宠物 →「优先技能」→ 选择该宠已学的主动技能；选定后立即启用技能优先。直接选择「技能优先」但尚未配置技能时，会打开技能选择菜单。行动模式为普攻、技能优先或全程防御；「低血防御」为独立开关，可与技能优先同时开启。开启后宠物血量达到或低于最大血量30%时先防御，恢复到30%以上后继续按原模式使用技能或普攻；切换行动模式、选择优先技能不会关闭低血防御。例如选择宠物 →「优先技能」→ 护卫，再点击「低血防御（30%及以下）」开启，两项同时保存。原「低血防御」模式配置自动兼容为技能优先＋低血防御开启。

默认攻击目标改为**属性克制优先**，按宠物当前四属性与敌人属性使用原生比率判断，多个克制目标或没有克制目标时，选择当前血量最低的可攻击敌人（同血按站位）。例如到五宠指挥官选择某宠物 →「攻击目标」→「属性克制优先」；原「最低血敌人」配置自动采用新规则，手动「前排优先／随机敌人」仍可使用。

护卫仅在其他存活队友生命低于 **50%** 时使用（恰好 50% 不触发），优先保护低血主角，否则保护当前血量最低的低血宠物；没有护卫目标时使用可单独配置的「护卫备用攻击技能」，未配置、遗忘或缺魔时普攻。例如选择某宠物 →「优先技能」→ 护卫，再选「护卫备用攻击技能」→ 已学的攻击技能；备用技能只接受攻击技能，可选「不使用技能（普攻）」清除配置，并随该宠 AI 保存。

攻击技能施放前会保守预估当前目标的普攻伤害，预计可一击击杀且普攻可到达时改用普攻，预估包含攻防差、原生属性／种族比率、防御减伤及 25% 余量，不依赖必杀或合击；有吸收、反射、物理无效等特殊状态时不作此替换，治疗、复活和护卫仍按原条件执行。治疗寻找生命比例低于 70% 的队友，复活寻找倒下的队友，魔力不足或没有有效目标时回退到普攻。被动或暂不支持自动施放的技能会明确标注。

本次 AI 更新在结束战斗后执行 `/module reload fivePet` 生效；同步新 `/help` 说明再执行 `/module reload gameQoL`，或正常重启服务端。

每只自动宠物可单独开关「**BOSS合击优先**」：BOSS 战中优先普攻，人物普攻时跟随其有效目标，否则集中攻击同一最低血量敌人，由原生普攻规则触发合击。普通战斗仍使用已配置技能；全程防御与低血防御的条件先执行。开关随该宠 AI 配置保存，主宠继续手动操作。

## 玩家命令

在游戏聊天窗口输入命令。`gameQoL`、`/fight`、`/difficulty` 和 `/selfKickOut` 的英文命令不区分大小写；五宠及技能库命令按示例输入。背包页和宠物栏位从 **0** 开始编号；当前配置有 **4 页背包（0～3）**，每页 20 格，宠物栏位为 **0～4**。下文 `[参数]` 表示可选参数，`on|off` 等表示任选其一；实际输入时不加这些方括号或竖线。

### 帮助查询

| 命令 | 作用 | 用法示例 |
| --- | --- | --- |
| `/help` | 按功能显示当前已加载的全部玩家命令及参数；完整用途通过单条查询查看 | `/help` |
| `/help 命令名` | 查询单个命令，支持英文名、中文别名及带 `/` 的名称 | `/help difficulty`、`/help 技能库`、`/help /bag` |
| `/help gm` | 显示当前已加载的 Lua GM 命令及参数，需要管理员权限 | `/help gm` |

例如先输入 `/help difficulty` 查看用法，再输入 `/difficulty 3` 切换为极难。未加载模块的命令不会出现在帮助中；普通玩家不能查询 GM 用法。`/help gm` 同样显示用法列表，完整说明可用 `/help giveItem` 等查询。帮助消息每条最多 120 个 GBK 字节，长说明按完整汉字分行，避免超长聊天记录；例如 `/help fivepet`。帮助显示修复由 GM 执行 `/module reload gameQoL` 或重启服务端后生效。

### 角色与战斗

| 命令 | 作用 | 用法示例 |
| --- | --- | --- |
| `/where` | 查看自己的地图、地图类型和坐标 | `/where` |
| `/heal` | 不带参数；免费清除人物及所有携带宠物的受伤，并补满生命、魔力；战斗、摆摊或五宠战斗结算期间不能使用 | `/heal` |
| `/fight [1～10]` | 在当前位置遇敌；数字指定敌人数，省略则使用地图正常随机数量；需有生命值且不在战斗中，组队时由队长使用 | `/fight`、`/fight 10` |
| `/clock` | 查看打卡状态和剩余卡时 | `/clock` |
| `/clock on` | 开启原生卡时双倍经验，需要剩余卡时 | `/clock on` |
| `/clock off` | 关闭打卡，同时关闭自动打卡 | `/clock off` |
| `/clock full` | 按 `gmsv/cgmsv.cf` 的 `fevermax` 补满卡时（当前 6 小时）并立即开始原生双倍经验打卡；战斗或摆摊时不可用 | `/clock full` |
| `/qol` | 查看自动功能开关及卡时 | `/qol` |
| `/fivepet on`、`/fivepet off` | 单人五宠默认开启，条件满足后自动启动；显式关闭会保存，AI 设置到五宠指挥官处配置 | `/fivepet off`、`/fivepet on` |

使用 `/clock full` 可补满卡时并开始打卡，例如先 `/clock off`，再 `/clock full`。由 GM 执行 `/module reload gameQoL` 或重启服务端后生效。

`/fight 10` 指定遇到 10 个敌人，`/fight 1` 指定 1 个；只接受 1～10 的整数，不带数字的 `/fight` 保持地图正常随机遇敌。怪物种类、等级沿用当前位置的原生选择，指定数量后可重复该次选中的怪物。地图必须允许遇敌，在城镇等无法遇敌的位置使用会显示失败提示。由 GM 执行 `/module reload fight` 和 `/module reload gameQoL`，或重启服务端后生效。

战斗结束后输入 `/heal` 即可清除自己和所有携带宠物的受伤，并恢复生命、魔力，包括生命为 0 的宠物；组队时只治疗自己及自己的宠物。宠物残留的旧战斗编号或模式不会阻止治疗，仍在实际参战名单中的宠物会被拦截。命令仅支持英文，不带参数；输入 `/help heal` 查看用法。新增命令需重载 `gameQoL`（GM 输入 `/module reload gameQoL`）或重启服务端加载。

五宠模式需携带 1～5 只存活宠物、选定一只主宠，并离开其他玩家队伍，有几只上几只，宠物固定前排、人物后排，满足条件后自动启动。输入 `/fivepet off` 关闭并保存设置，`/fivepet on` 恢复开启；主宠手动，其余宠物 AI、优先技能和 BOSS 合击优先到圣殿 `16,34` 的五宠指挥官处设置。此次 Lua 修复可在结束战斗后由 GM 重载 `fivePet`，或正常重启服务端生效。

### 自动功能

每项命令接受 `on` 或 `off`，开关按账号和角色保存。当前默认值如下：

自动鉴定、自动卖魔石、自动整理、自动堆叠、自动打卡与战后自动修理均默认 **on**；单人五宠也默认 **on**，并按上文条件自动启动。角色显式保存的关闭设置继续保留，可使用对应的 `on` 命令恢复。

| 命令 | 功能 | 默认状态 | 示例 |
| --- | --- | --- | --- |
| `/autostack` | 自动合并可堆叠道具 | 开启 | `/autostack off` |
| `/autosort` | 自动整理所有背包页，战斗结束后执行等同 `/sort all` 的整理 | 开启 | `/autosort off` |
| `/autoidentify` | 自动免费鉴定 | 开启 | `/autoidentify off` |
| `/autosell` | 自动出售已鉴定魔石 | 开启 | `/autosell off` |
| `/autoclock` | 有剩余卡时时自动开启打卡 | 开启 | `/autoclock off` |
| `/autorepair` | 战斗结束后检查已装备物品，耐久低于最大耐久的 85% 时免费修满 | 开启 | `/autorepair off`、`/autorepair on` |

背包等自动任务每 2 秒检查一次；战斗或摆摊期间暂停自动处理。战后任务每 250 毫秒检查是否已真正离开战斗，确认后整理**全部背包页**，保留当前选中的背包页，各页物品不跨页搬移。

自动修理只检查人物当前装备栏（原生栏位 `0～7`），不修理背包里的备用装备；免费恢复到该装备当前的最大耐久，不降低最大耐久。耐久恰好为 **85% 不修理**，低于才修理；例如 `84/100` 修为 `100/100`，`85/100` 保持原样。最大耐久为 0 的物品跳过。

输入 `/qol` 可以看到 `autosort`、`autorepair` 等开关；`/help autorepair` 和 `/help autosort` 可查询用法。首次使用时两项默认开启，已明确保存的开关继续按角色设置；需要恢复开启时输入 `/autosort on`、`/autorepair on`。

### 技能效果示例

## 物品和宠物存档问题排查

若保存时出现 `Column count doesn't match value count` 或列数不匹配错误，先确认服务端使用的数据库类型以及数据库结构是否与当前程序匹配。

1. 查看 `gmsv/setup.cf` 的 `dbengine`：`1` 为 SQLite，`0` 为 MySQL。
2. 对照当前版本表结构检查报错表。SQLite 参考 [sqlite.sql](gmsv/sql/sqlite.sql)，MySQL 参考 [mysql.sql](gmsv/sql/mysql.sql)。初始化脚本用于新数据库，已有存档不能重新初始化。
3. SQLite 可通过以下查询查看字段及顺序，再与初始化结构对照；按实际缺少或错位的字段制定迁移。

   ```sql
   PRAGMA table_info(tbl_item);
   PRAGMA table_info(tbl_pet);
   ```

4. 修改已有数据库前正常关闭服务端并备份存档。修复后验证道具和宠物在正常保存、退出、重启后仍能恢复。

数据库账号、密码和库名以 `setup.cf` 为准。当前仓库提供 HTTP 账号注册页，不包含数据库管理网页。
