# moli-2026 服务端

本仓库保存 CrossGate 服务端及其维护工具。

- `gmsv/`：服务端程序、GBK 控制台适配器、Lua 模块、NPC 脚本和静态地图/游戏数据。
- `tools/`：服务端内容整合、修复和验证工具。

客户端程序、图像、音效、客户端地图缓存、显示/语言工具，以及备份、日志、玩家数据库和运行存档不纳入版本控制。根目录采用白名单，避免后续 `git add .` 误加入客户端。

## 在新机器准备服务端

1. 将 `gmsv/setup.cf.example` 复制为 `gmsv/setup.cf`，填写数据库、GM 和服务间登录口令；模板保留原文件的 GBK 编码。
2. 将 `gmsv/data/debugger.txt.example` 复制为 `gmsv/data/debugger.txt`，按需要填写允许的 GM 账号。
3. SQLite 初始化结构在 `gmsv/sql/sqlite.sql`，仅包含表结构和服务端迁移版本记录，不含账号、角色、道具或宠物存档。仅在没有 `gmsv/data.db3` 的新环境中执行：

   ```powershell
   if (Test-Path gmsv/data.db3) { throw '数据库已存在，请保留现有数据。' }
   python -c "import sqlite3; from pathlib import Path; c=sqlite3.connect('gmsv/data.db3'); c.executescript(Path('gmsv/sql/sqlite.sql').read_text(encoding='utf-8')); c.close()"
   ```

   MySQL 的初始化脚本为 `gmsv/sql/mysql.sql`，切换数据库时同步修改 `setup.cf`。
4. 在 `gmsv` 下创建运行目录 `store`、`store/dungeon`、`store/house`、`store/itemcount`、`Dengon`、`dump`、`GMLog` 和 `house`。迁移已有服务器时，另行复制数据库和运行存档。
5. 从 `gmsv` 目录启动 `cgmsv-gbk.exe`；该适配器会启动同目录的 `cgmsv.exe`。

   ```powershell
   Set-Location gmsv
   .\cgmsv-gbk.exe
   ```

原有文件不转换编码或换行。服务端地图虽然是二进制文件，仍属于服务端必需的静态资源。

## 客户端连接与账号注册

1. 另行准备兼容的游戏客户端、资源及登录器；这些文件不包含在本仓库中。7.1 客户端资源对应关系见[宠物导入指南](docs/cg71_pet_import_guide_zh.md)。
2. 启动服务端后，将登录器的服务器地址指向本机 `127.0.0.1`；在其他电脑上连接时填写服务端所在电脑的地址。游戏端口以 `gmsv/setup.cf` 的 `port` 为准，模板为 `9030`。
3. 在服务端电脑打开[账号注册页面](http://127.0.0.1:10086/)，注册账号和密码，然后通过登录器进入游戏。HTTP 注册服务由 `http` 模块提供，当前监听端口为 `10086`。

默认加载的模块见 [ModuleConfig.lua](gmsv/lua/ModuleConfig.lua)。下列玩家命令来自已加载的 `gameQoL`、`fight`、`fivePet`、`skillLibrary`、`gameDifficulty` 和 `autoUnlock` 模块。`/help` 只显示当前已加载模块的命令。

## 特色玩法与 NPC 入口

走上**法兰城东门医院附近 `223,85`** 的「圣殿传送石」，即可自动免费进入**圣殿，地图 60003**。65 位职业导师、一个 BOSS 技能导师、十间分级装备店和宠物／成长服务集中在同一房间。生产系、物理战斗系、法系各排一行，导师之间空一格；没有内部往返传送石。走上圣殿 `32,34` 的「法兰返程石」自动返回医院附近 `223,86`；聊天输入 `/where` 可以查看自己的位置。

宠物穿装入口：到圣殿 `48,27` 右键「宠装管理员」→选择携带宠物→第一项「一键装备背包宠装」，按背包第0页顺序给空槽穿上已鉴定、未损坏且符合原生条件的宠装，保留已穿装备。例如背包有宠服、宠圈、宠晶和宠饰时，一键填入身体、项圈、晶石及一个饰品槽；宠服和宠甲按背包顺序择一，同类型饰品依原生规则只能穿一件。完成后立即显示五个槽位的实际装备名称。商人出售的R1／R5／R10／R15分别需要宠物1／40／90／140级，按宠物等级检查；20级宠物可穿R1。背包装备列表显示所需宠物等级；一键失败会显示背包宠装件数及具体原因（等级不足、未鉴定、损坏或同类饰品冲突）。也可选「穿上背包里的宠装」或点击空槽，单件选装备→空槽→原生确认窗口选「是」；卸装点击已穿装备再确认，背包第0页需留空位。宠服和宠甲共用身体槽，项圈与晶石各一个槽，饰品两个槽但同类型只能穿一件。免费，非战斗、非摆摊且五宠结算完成时操作；换宠、道具移动、过期确认均需重新选择。只需GM执行现有 `/module load petEquipment`（已加载时用 `/module reload petEquipment`）加载本次NPC功能；也可正常重启。本次穿卸代码不需要更新客户端。

四位商人仅出售商品，使用原生商店扣费与背包检查。从南侧接近，例如到圣殿 `36,27` 右键「宠物装备商人」购买宠服R1（1000魔币）；血瓶到 `40,27`，料理到 `44,27`。属性水晶商人到 `32,27`：地、水、火、风纯属性各1000魔币，地水、水火、火风、风地5:5各400魔币，共8种。新增水晶商人只改Lua，GM执行 `/module reload sanctuaryShops` 生效，无需重启；使用与宠装商人相同的原生商店，在NPC库存实例上设置售价，不改水晶DATA。运行 `python tools/sanctuary/shops_install.py` 同步源码和GBK运行文件、登记模块及宠装价格后，正常保存并退出游戏、重启服务端生效（本次含道具价格表更新）。

### 自动加点

与自动加点师对话，先选人物或某只随身宠物，也可选择「配置银行宠物」进入银行五栏列表，再选单项全加或自定义。例如为银行宠物1选择「全加力量」，以后升级新增点数自动加力量。输入的是**比例，不是固定点数**，顺序为**体力、力量、强度、速度、魔法**。例如 `1 2 0 1 0` 按 `1:2:0:1:0` 分配本次升级新增的点数；整数舍入进度跨等级累计保存。五项均为非负整数，合计必须在 1～100。

新角色、新宠物默认关闭，选定或保存方案后开启。原有剩余点数保留，不执行洗点；人物遵守单项等级上限，宠物种族自然成长照常计算。每只宠物按唯一编号保存方案，换栏位不会串配置，重登和重启后保留。银行宠物参与宠物小队获得经验后同样自动分配升级新增点数。结束战斗后 GM 执行 `/module reload autoStat`，或正常重启生效。详见[自动加点说明](docs/auto_stat/使用说明.md)。

### 宠物忠诚度

宠物忠诚度默认固定为 **100**，无需学习调教或输入命令。新获得与已有宠物在创建、属性重算、登录、战斗与保存时保持基础和实际忠诚度为 100；自动维护也会修正携带宠物，不受背包自动功能开关、战斗或摆摊限制。正常收宠仍可操作，宠物不会因忠诚度不足而发呆、乱行动或逃跑。

配置位于 `gmsv/cgmsv.cf`（`defaultloyalty=100`、`maxloyalty=100`）及 `gameQoL` 模块。正常保存角色并重启服务端后完整生效；运行中可先用 GM 命令 `/module reload gameQoL` 加载忠诚锁定逻辑，已有携带宠物将在自动维护时恢复到 100。

本引擎的宠物行为回调以 6 为正常分支：模块恢复回调传入的原始技能、目标与指令，并返回 6，避免额外发送“不听话”动画或改成普攻。返回 8 仍会发送不听话动画，不能用作正常分支；手动收宠分支保留。

### 魔石强化装备（最高 +13）

先输入 `/autosell off` 保留普通魔石，再把魔石拖到人物背包中的装备所在格子，每次尝试消耗 **1 颗**，成功强化 **+1**，最高 **+13**，满级不消耗材料。例如：魔石拖到长剑上，成功后长剑变成 `长剑+1`。堆叠魔石每次拖放也只消耗 1 颗，失败也消耗材料，任务魔石不参与强化。

每级给装备原始正数攻击、防御、敏捷、精神、回复、生命、魔力、魔攻累计增加 **7%**，计算为 `floor(原始属性 × (1 + 0.07 × 强化等级))`；零值和负值保持原值。不是复利：原始攻击 100，+1 为 107，+7 为 149，+13 为 191；降级同步回退对应加成，后续宝石等外部增量保留。强化等级、原始属性和连续失败次数保存在装备本身，随装备保存和转移。

| 本次目标等级 | 成功率（按等级依次列出） | 失败时降级规则 |
| --- | --- | --- |
| +1～+7 | 95%、93%、91%、89%、87%、85%、82% | 不降级 |
| +8～+11 | 79%、77%、75%、72% | 50% 概率降 1 级，否则保持 |
| +12～+13 | 62%、55% | 80% 概率降 1 级，否则保持 |

降级概率只在本次强化失败后判定，并以本次**目标等级**划分。例如 +7 冲 +8 失败，有 50% 概率变成 +6；+11 冲 +12 失败，有 80% 概率变成 +10。**连续失败 5 次后，第 6 次必定成功**；失败降级不清空计数，成功清零，转移装备不清空计数。失败提示显示当前计数或“下次强化必定成功”。

支持人物装备（类型 0～14）与宠物装备（类型 56～60）；已穿戴的装备均须先卸到人物背包。装备须已鉴定且耐久大于 0，战斗或摆摊期间不能强化。装备的原有说明和特殊参数保留；其他旧强化系统标记或异常强化数据暂不支持，拒绝时保留魔石。强化数据使用原生 `Item.GetExtData` / `Item.SetExtData` 扩展字段，随正常装备存档保存。

新增模块 `equipmentEnhance` 已加入启动配置。现有服务端由 GM 首次执行 `/module load equipmentEnhance`（已加载时用 `/module reload equipmentEnhance`），然后 `/module reload gameQoL`，或重启服务端后生效。配置在 `tools/equipment-enhance/equipmentEnhanceData.lua`，修改后运行 `python tools/equipment-enhance/install.py` 同步 GBK 副本；成功率、降级率按目标等级索引，保底阈值为 `pityFailures=5`。隔离验证：`python tools/equipment-enhance/verify.py`，仅使用临时角色，不访问玩家数据库。

### 自动功能

每项命令接受 `on` 或 `off`，开关按账号和角色保存。当前默认值如下：

自动鉴定、自动卖魔石、自动整理、自动堆叠、自动打卡与战后自动修理均默认 **on**；单人九宠也默认 **on**，并按上文条件自动启动。角色显式保存的关闭设置继续保留，可使用对应的 `on` 命令恢复。

| 命令 | 功能 | 默认状态 | 示例 |
| --- | --- | --- | --- |
| `/autostack` | 自动合并可堆叠道具 | 开启 | `/autostack off` |
| `/autosort` | 自动整理所有背包页，战斗结束后执行等同 `/sort all` 的整理 | 开启 | `/autosort off` |
| `/autoidentify` | 自动免费鉴定 | 开启 | `/autoidentify off` |
| `/autosell` | 自动出售全部背包内已鉴定的普通魔石，包含普通战斗掉落 | 开启 | `/autosell off`、`/autosell on` |
| `/autoclock` | 有剩余卡时时自动开启打卡 | 开启 | `/autoclock off` |
| `/autorepair` | 战斗结束后检查已装备物品，耐久低于最大耐久的 85% 时免费修满 | 开启 | `/autorepair off`、`/autorepair on` |

背包等自动任务每 2 秒检查一次；战斗或摆摊期间暂停自动处理。战后任务每 250 毫秒检查是否已真正离开战斗，确认后整理**全部背包页**，保留当前选中的背包页，各页物品不跨页搬移。

`/autosell on` 开启后，战后及每 2 秒自动出售全部背包中的普通魔石；`/autoidentify on` 开启时先鉴定再出售。识别包含鉴定前名称为“魔石？”的普通战斗掉落，不出售受污染的魔石、魔石转化器等任务道具；金币容量不足时保留对应魔石。此次魔石名单修复需 GM 执行 `/module reload gameQoL` 或重启服务端生效。`/autosort` 默认开启；角色已保存为关闭时，输入 `/autosort on` 保存开启。

自动修理只检查人物当前装备栏（原生栏位 `0～7`），不修理背包里的备用装备；免费恢复到该装备当前的最大耐久，不降低最大耐久。耐久恰好为 **85% 不修理**，低于才修理；例如 `84/100` 修为 `100/100`，`85/100` 保持原样。最大耐久为 0 的物品跳过。

输入 `/qol` 可以看到 `autosort`、`autorepair` 等开关；`/help autorepair` 和 `/help autosort` 可查询用法。首次使用时两项默认开启，已明确保存的开关继续按角色设置；需要恢复开启时输入 `/autosort on`、`/autorepair on`。

## 技能与职业配置

以下技能与职业配置文件使用 **GBK 编码、Tab 分隔**。下文列号均从 **1** 开始，并计入空列；编辑时必须保留空列，不能用空格拆分后重新拼接。Lua API 的 `CONST.TECH_*` 等索引是内存字段索引，不能直接当作文本文件列号。

### skill.txt：技能基础定义

以下是当前 `乾坤一掷`（技能 ID `3`）的主要字段：

| 实际列号 | 字段 | 当前值 | 说明 |
| --- | --- | --- | --- |
| 1 | 名称 | 乾坤一掷 | 技能名称 |
| 2 | Skill ID | 3 | 技能定义编号，供 `tech.txt`、`skilllv.txt` 关联 |
| 3 | 说明编号 | 130003 | 说明资源编号，不是招式的 Tech ID |
| 4 | 技能类别 | 1 | 沿用对应技能的原生类别 |
| 5 | 基础等级上限 | 30 | 当前配置已扩展至 30 级；职业许可另看 `skilllv.txt` |
| 7 | 学习费用 | 100 | 技能库使用此字段作为普通技能的学习费用 |
| 9 | 武器限制 | 159 | 原生武器限制掩码，修改时参考同类技能 |
| 10 | 经验表编号 | 2 | 关联 `skillexp.txt` 的经验表 |
| 11 | 技能栏占用 | 1 | 装配时占用的技能栏数 |

其他字段和空列应从现有模板保留。以下示例用 `\t` 表示一个真实 Tab（包括末尾空列）；写回 DATA 时需还原为 Tab。当前记录示例：

```text
乾坤一掷\t3\t130003\t1\t30\t1\t100\t100\t159\t2\t1\t\t1000\t\t\t\t0\t\t
```

### tech.txt：招式与实际效果

同一个 Skill 可以关联多个等级的 Tech。当前表每条记录有 **15 列**；以乾坤一掷 LV1 为例：

| 实际列号 | 字段 | 示例值 |
| --- | --- | --- |
| 1 | 招式名称 | 乾坤一掷LV1 |
| 2 | 效果处理器 | `TECH_Parameter` |
| 3 | 效果参数 | `AS:0,HR:-2,DD:10,` |
| 4 | Tech ID | 300 |
| 5 | 说明编号 | 130003 |
| 6 | 关联的 Skill ID | 3 |
| 7 | 技能等级或原生宠物/BOSS 标记 | 1 |
| 8 | 使用场景类别 | 1 |
| 9 | 目标范围码 | 1141 |
| 10 | COST 字段 | 空 |
| 11 | DRESSAGE 字段 | 空 |
| 12 | 魔力消耗 | 10 |
| 13 | 使用者标志 | 1（人类）；0 表示宠物 |
| 14、15 | 配方相关字段 | 空 |

```text
乾坤一掷LV1\tTECH_Parameter\tAS:0,HR:-2,DD:10,\t300\t130003\t3\t1\t1\t1141\t\t\t10\t1\t\t
```

第 7 列中，原生记录的 `30`、`50` 可分别作为宠物、BOSS 技能标记。本服另外建立了玩家 1～30 级的招式记录，因此应结合第 13 列及关联的 Skill 判断，不能只凭 `30` 就认定是宠物技能。

技能 ID、Tech ID、说明编号是不同字段。新增技能要给 Skill 和 Tech 分别选取未占用的编号，再通过 Tech 的第 6 列关联 Skill。动画表现需结合原生处理器和客户端资源验证。

### 技能效果示例

`TECH_ContinuationAttack` 的参数示例：

```text
AS:0,AN:2,AM:2,DD:80,
```

以下是常用参数的含义；实际支持哪些参数取决于处理器：

| 参数 | 含义 |
| --- | --- |
| `AN`、`AM` | 连续攻击次数相关参数 |
| `DD` | 伤害修正；`DD:80` 为增加 80% 的伤害修正 |
| `HR` | 命中修正 |
| `TR` | 攻击力修正，与伤害修正 `DD` 不同 |
| `AV` | 闪避修正 |
| `CR` | 必杀修正 |
| `AR` | 回复量相关参数，例如 `TECH_Revive` 的 `AR:6000` |

不能保证增加一个参数就能对所有处理器生效，也不能将攻击次数等同于必定攻击不同目标。当前定制技能的实现与验证方法见[职业技能包](docs/jobskill_pack/README_zh.md)。

## 物品和宠物存档问题排查

若保存时出现 `Column count doesn't match value count` 或列数不匹配错误，先确认服务端使用的数据库类型以及数据库结构是否与当前程序匹配。

1. 查看 `gmsv/setup.cf` 的 `dbengine`：`1` 为 SQLite，`0` 为 MySQL。
2. 对照当前版本表结构检查报错表。SQLite 参考 [sqlite.sql](gmsv/sql/sqlite.sql)，MySQL 参考 [mysql.sql](gmsv/sql/mysql.sql)。初始化脚本用于新数据库，已有存档不能重新初始化。
3. SQLite 可通过以下查询查看字段及顺序，再与初始化结构对照；按实际缺少或错位的字段制定迁移。

   ```sql
   PRAGMA table_info(tbl_item);
   PRAGMA table_info(tbl_pet);
   ```

4. 修改已有数据库前正常关闭服务端并备份存档。修复后验证道具和宠物在正常保存、退出、重启后仍能恢复。

数据库账号、密码和库名以 `setup.cf` 为准。当前仓库提供 HTTP 账号注册页，不包含数据库管理网页。
