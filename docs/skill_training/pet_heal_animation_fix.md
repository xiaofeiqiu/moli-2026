# 宠物超强补血魔法 E1 闪退兼容修复

症状：主宠使用超强补血魔法 E1 后客户端闪退，服务端继续运行。根目录客户端转储 `cgmsv.1DD5917A043DE6E.crash.dmp` 记录了 `cgmsv.exe` 内的访问违规 `0xC0000005`，故障地址 `0x4329E7`（模块偏移 `0x329E7`），无效读取地址 `0x46467C3C`。转储确认客户端异常，但不能单凭这个地址确定触发招式。

发现的兼容问题：宠物导师原来同时列出原生 E1（6350）和同名复制 E1（700826）。两条 DATA 的回血函数、AR:50、群体目标和 48 MP 消耗一致，只有 Tech ID 和所属 Skill ID 不同。客户端按招式编号选择动画类别，复制编号与原生编号进入不同类别。此次修复针对复制编号的兼容问题；尚未通过真实客户端重现、修复前后播放对照确认它就是本次闪退的唯一原因。

修复：`petSkillTutor` 在回合开始前，将主宠与五宠代理的第一、第二行动栏中复制 E1 的补血指令映射为原生 6350。已学技能编号和五宠 AI 规则不变，无需遗忘重学。模块加载时校验两条 DATA 的函数、参数、等级、目标及耗魔一致。人物指令及其他战斗命令不参与映射。

导师目录只保留原生 6350；已学 700826 的宠物再次选择原生 E1 时按重复技能处理，不扣钱。`training_build.py` 以后重建目录时也会排除复制项。维护工具 `python tools/skill-library/pet_heal_install.py` 同步 UTF-8 源码、GBK 运行副本及教学目录，保留 Lua 原文件换行，不改 DATA 或玩家存档。

生效：结束战斗后由 GM 输入 `/module reload petSkillTutor`，随后重新登录客户端复测。无需重启服务端。该模块重新加载教学目录，不需要额外重载其他导师模块。

验证：`python tools/skill-library/training_verify.py pet_heal_battle` 使用隔离服务端、独立端口和空 SQLite 数据库，872 项检查通过。覆盖原生及复制 E1 的主宠手动、五宠 AI 四种场景；校验两个行动栏的映射、真实群体回血、每次 48 MP、已学技能和 AI 规则保留、复制技能不再出现在教学目录、重复学习不扣费及热重载后只注册一个回调。捕获的四个场景均发出 `SKL|s18CE|`（6350），未发出 `SKL|sAB19A|`（700826）。人物指令与无关攻击指令保持原样。详细记录见 `pet_heal_battle_native_result.json`。

验证边界：已确认服务端实际结算和发出的动画编号；尚未在可见客户端中完成动画播放复测。若热重载并重新登录后原生 E1 仍闪退，需要结合新的客户端转储继续定位。
