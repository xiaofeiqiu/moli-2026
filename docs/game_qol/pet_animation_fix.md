# 主战宠“不听话”动画修复

现象：忠诚度 100、人物和宠物均为 1 级时，宠物先播放“不听话”，随后执行指令。

当前 `gmsv/cgmsv.exe` 的行为回调与接口参考中的枚举说明不一致。正常情况下，底层向 `BattlePetLeaveCheckEvent` 传入 `6`；旧修复将它改为 `8`。底层只有 `6` 会跳过“不听话”输出，`8` 仍会生成 `PNO|a5|`，所以每回合出现多余动画。

底层还可能在调用回调前修改战斗指令。现在 `gameQoL` 恢复回调参数中的原指令、目标和 Tech ID，然后返回 `6`。既有的 `1` 分支保持原行为。

已同步 UTF-8 源码与 GBK 运行模块。非战斗状态由 GM 执行 `/module reload gameQoL`，或保存角色后重启服务端，在下一场战斗生效。

复查：`python tools/game-qol/help_verify.py pet_animation`。使用独立服务端、独立端口、临时人物与宠物；只读取该测试进程的战斗输出，不修改玩家数据库。

测试对照包括旧返回值 `8`，以及运行模块的普攻和陨石魔法指令。旧分支输出 `PNO|a5|SKL|s1C84|...`；修正后输出对应的 `SKL|...`，没有 `PNO|`，原目标和指令保留，魔法按原耗魔执行。结果见 [pet_animation_native.json](pet_animation_native.json)。该检查验证服务端动画指令，不包含客户端画面录制。

本次使用的服务端 SHA256：`bc69e795441d0819e547b569e4df3eae97278176e047cc829a36d19a6072cd76`。其他版本的行为和战斗输出地址需要重新核对。
