# 魔剑士任务兼容与验证范围

2026-10-10，按“剑士或魔法师能做的任务，魔剑士也能做”的要求，兼容当前安装的任务脚本。

## 职业与职阶规则

魔剑士职业 ID 为 `181～187`，职业类别为 `180`。每个职阶同时满足对应剑士 `11～17` 或魔法师 `71～77` 的任务职业判断。例如，`185` 可以通过原本要求剑士 `15` 或魔法师 `75` 的职业判断；要求更高职阶的任务仍需达到对应职阶。

普通 Event 脚本中的 `Job` 和 `JobAncestry` 条件编译为原生 `Luac` 调用，由 `sharedTaskAdapters` 调用 `magicTaskJobs` 进行判断。共享任务旧职业名单也按此规则检查。相关职业晋阶奖励如果原本写入剑士或魔法师职业，会改写为对应魔剑士职阶，并保留职业类别 `180`。

等级、声望、道具、任务前置、单人或队伍要求及奖励次数继续按任务原条件检查。其他职业沿用原职业判断。

## 扫描与验证

- 扫描当前 `gmsv/data/npc` 的 13,166 个脚本，覆盖 4,546 组职业及职业类别表达式；修改 53 个脚本的 283 处判断，生成 28 个去重判断。
- 使用独立服务端、测试端口 `19074` / `19174` 和只含表结构的 SQLite 数据库，验证魔剑士七个职阶及现有其他职业的判断结果。
- 使用实际任务适配器验证全部原生共享职业名单，以及剑士、魔法师两条晋阶奖励保留魔剑士身份。
- 验证极限挑战入口允许魔剑士七个职阶、目的地 `60110,16,23` 已加载且可走，原生传送成功；游民限制和远距离交互限制继续生效。
- 验证三个重叠点的热搬移、正常重启、重复执行和目标格站着玩家的情况；固定 NPC 占位会在移动前拒绝执行。两个任务向导入口可实际传送到新接待位置。

这些检查覆盖脚本职业条件、晋阶写入和相关传送，不等于逐个任务完成整条剧情，也没有通过正式角色进行客户端点击验收。没有读取、复制或修改正式玩家数据库。

## 生效与维护

正常保存角色并重启服务端，加载全部 Event 脚本和静态 NPC 新位置。运行中也可先输入 `/dofile lua/npcOverlapFix.lua`，立即搬移重叠 NPC 并重载任务适配器，修复极限挑战的职业入口；全部 Event 脚本以正常重启加载为准。

维护工具为 `tools/npc-overlap/repair_sign_stone.py`。源模板为 `tools/content-audit/templates/sharedTaskAdapters.lua`，辅助库为 `tools/npc-overlap/magic_task_jobs.lua`，生成的判断源目录为 `tools/npc-overlap/magic_task_predicates.json`；运行副本保留 GBK 和原换行。

原始字节备份位于 `backups/npc_overlap_fix_20261004/revision3/original`。安装清单、扫描清单和原生验证结果位于 `docs/npc_overlap_fix/revision3`；生成报告和隔离数据库不进入 Git。
