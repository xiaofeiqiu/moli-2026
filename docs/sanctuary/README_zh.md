# 圣殿

法兰城东门医院附近 `223,85` 的「圣殿传送石」免费送入圣殿（普通地图 `60003`），落点 `24,36`。圣殿 `32,34` 的「法兰返程石」送回医院附近 `223,86`。走上石头所在格自动传送，站在旁边不触发；也保留右键对话传送，战斗中不可使用。两端落点与石头分开，不会到达后立即传回。

圣殿采用独立的 100×50 地图，使用现有神殿石板与墙面资源重建开阔大厅。中央没有墙壁或门廊，所有服务 NPC 远离边界墙并保留通路，落点与 NPC 分开。此次地图及布局修复需要先正常退出游戏，再正常关闭并重启服务端，重新登录加载。

## 对话与战斗状态修复

`battleState` 检查原生战斗队列。闲置玩家的非负战斗编号若不属于其真实战斗，恢复为 `-1`，解决回城后 `/skillbook` 仍提示“请在战斗结束后操作技能库”、宠装制造师和五宠指挥官不响应的问题。真实战斗成员保持原状态；非闲置状态只有在原生战斗已失效且连续确认超过三秒后才清除。不会调用正式角色的强制退战接口。五宠指挥官的对话距离改为读取自己的实际地图和坐标。

游民与职业进阶导师对话时会明确提示尚未就职，并可打开永久技能库、查看职业与BOSS导师位置或查看宠装职业就职说明；指导菜单不改变职业或扣费。已就职角色仍显示本职进阶技能。

踩踏传送通过原生 `Char.SetPostOverEvent` 触发。本次只改 Lua，GM 可使用 `/module reload sanctuary` 生效；也可正常重启服务端。地图与布局若尚未加载，则仍需正常重启。

2026-10-10 修复侧墙遮挡：职业导师三排向大厅内侧移 6 格，从 x=16 起；BOSS 技能导师移至 34,18，宠物技能导师移至 36,18。公共 NPC 创建器会缓存位置目录，本次需正常保存角色、退出游戏并重启服务端，再重新登录加载新坐标；仅重载导师模块不能完整刷新 BOSS 和宠物导师位置。

## 维护与验证

`tools/sanctuary/` 保存 UTF-8 源码，运行副本为 GBK。`sanctuaryData.lua` 统一配置服务位置；NPCPart 创建 NPC 时应用这些位置，各服务模块单独重载也会留在圣殿。

- `python tools/sanctuary/install.py`：检查地图编号冲突、生成独立地图、同步 Lua、注册模块及室内地图设置。
- `python tools/sanctuary/verify.py`：在独立空 SQLite 数据库和端口 `19230/19231` 验证地图、圣殿86个对象及城内入口、通路连通、菜单、实际 `Char.MoveArray` 行走踩踏往返、邻格不触发、落点不循环、音乐请求、失效战斗状态及真实战斗限制、各模块重载。
- `python tools/skill-library/training_verify.py`：验证65位职业导师、单个BOSS导师十项分页、人物宠物限制及宠物独立教学。
- `python tools/npc-overlap/audit_current.py`：复查全服新增 NPC，无同格重叠且可接近。
- `python tools/game-qol/verify_help.py`：验证玩家命令、帮助、README 和编码副本同步。

`python tools/sanctuary/preview.py` 使用客户端真实素材绘制布局，检查当前圣殿对象均不被前景墙面遮挡，预览为 `room_preview.png`。

宠物技能遗忘模块的 UTF-8 源码为 `tools/skill-library/petSkillTutor.lua`，使用 `python tools/skill-library/pet_skill_install.py` 同步 GBK 运行文件和位置目录。本次房间加宽、技能禁止许可与公共菜单函数需正常重启加载；位置为 `36,18`，从 `36,19` 接近。`python tools/skill-library/training_verify.py pet_forget` 验证技能分页、原生是／否二次确认、拒绝旧列表编号与错误窗口序号、取消／过期、换宠、状态限制、原生删除、失败恢复、重新学习和模块重载。原生引擎拒绝保存测试假人（返回 -3），因此成功保存分支使用注入验证；真实账号重登持久化未在此测试中验证。

测试使用临时角色，运行目录在 `backups/`，报告在本目录 `native_result.json`；不复制或修改正式玩家数据库。报告、日志和临时数据库不进入版本控制。
