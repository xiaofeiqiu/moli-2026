# 银行参战宠物经验修复

正常胜利后，实际参战且存活的银行前4栏宠物获得原生战斗经验，逐只提示所得经验，并保存到银行原宠。第5栏、未参战及倒下的银行宠物不分经验。

原生 `Pet.UpPet` 会检查随身宠物栏，对银行原宠返回 `-5`。旧代码虽然写入经验，却无法完成经验扣除、升级和成长。过去的九宠验证用随身宠物模拟银行查询，因此没有发现这个限制。

现在将原宠的等级、经验、五项基础属性、升级点、成长档和获取时等级同步到临时战斗宠物，执行原生升级，再写回银行原宠并重新计算装备后的最终属性。升级事件传给原角色和银行原宠，自动加点保留旧点数，只分配新增点数。结算后清空待发经验，避免重复发放。

验证使用独立服务端、空测试数据库及临时人物和宠物。测试工具仅在所启动的子进程内、核对服务端 SHA-256 和对象指针后布置真实银行栏；游戏模块不访问进程内存，银行查询保持原生接口。未读取或修改玩家数据库。

- 原版复现：银行宠物经验达到16时仍停留1级，原生升级失败。
- 真实银行验证：43项通过，覆盖四只参战宠物经验、跨级成长、自动加点、旧点数保留、银行身份与栏位、临时载体等级恢复、重复结算、倒下宠物及第5栏不分经验。
- 九宠回归：163项通过，包含3回合原生战斗、血魔受伤同步、经验回写、阵容变动和清理。
- 游戏内帮助：420项通过；命令目录检查通过，51个命令和别名与README及源码/运行副本一致。

执行 `python tools/five-pet/verify_nine.py bank_exp`、`python tools/five-pet/verify_nine.py nine`、`python tools/five-pet/verify_nine.py help` 和 `python tools/game-qol/verify_help.py` 可复验。原版比较可将备份源码作为 `verify_nine.main('bank_exp', five_pet_source=...)` 的第二个参数传入。

本机报告：[汇总](bank_exp_validation.json)、[真实银行](bank_exp_native.json)、[原版复现](bank_exp_before.json)、[九宠回归](bank_exp_nine.json)、[帮助](bank_exp_help.json)。真实客户端显示及玩家存档重登尚未实测。

结束战斗后，GM依次执行 `/module reload fivePet`、`/module reload autoStat`、`/module reload gameQoL`，或正常重启服务端生效。
