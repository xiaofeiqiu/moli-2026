# CrossGate 7.1 内容补齐计划

目标是识别并补齐当前 5.5 服务端 DATA 相对于 7.1 客户端缺少的地图、任务、人物技能、6.0 至 7.1 新职业及相关物品。宠物由另一个 agent 处理，本任务不修改宠物基础表、宠物模板及其测试文件。

客户端资源只能证明某些素材存在，不能直接提供完整的服务端任务流程、奖励、地图出口或技能公式。以本地有效配置和可核实的官方资料为依据；无法确认的内容列入待补清单，不用旧内容改名来充当新版本内容。

## 工作阶段

1. **建立基线和差异清单。** 解析实际加载路径，盘点地图、NPC 参数脚本、传送关系、技能、等级表、职业表、物品和客户端资源。记录编号、名称、文件、重复项、依赖和来源可信度。将状态分为已有、缺失且可补、来源待确认、引擎待支持。
2. **优先处理地图。** 对照地图文件的内部编号、尺寸及层数据，检查碰撞、出口和任务引用。仅从完整且格式明确的来源导入缺失地图；客户端缓存与服务端原始地图需要分别验证。先处理引用缺失和完整地图包，再处理新增区域的入口。
3. **按完整任务链补齐。** 每个任务核对入口条件、NPC、对话、事件标记、任务道具、战斗和奖励，检查重复完成与中途退出。保留来源和实现说明；依赖宠物或怪物配置时记录接口需求，由负责该表的 agent 协调。
4. **补齐人物技能。** 建立技能到等级定义、战斗函数、职业限制和学习 NPC 的映射。确认引擎已有实现后增加缺失定义；需要 Lua 实现的技能必须有明确公式及行为资料，并验证资源消耗、目标选择、失败条件和升级规则。
5. **核对并补齐新职业。** 核实台湾 6.0 至 7.1 是否新增职业，区分客户端版本、地区版本和其他衍生游戏。每个职业同时核对职业表、晋阶称号、就职任务、得意技能、等级上限、装备与学习限制及学习 NPC；已有职业不重复创建。需要引擎支持的规则单独验证。
6. **补齐关联内容。** 在地图和任务实际需要时加入物品、商店、配方、称号和传送配置，避免无来源地批量开放内容。
7. **分批验证和交付。** 生成可重复运行的静态检查工具；每批修改先备份目标文件并记录哈希，保持原文件编码。检查编号唯一性、引用、地图尺寸和脚本参数；再进行服务端加载及游戏内验证。每批附回滚办法、完成清单与仍缺资料的清单。

## 实施约束

- 服务端正在运行，修改磁盘不代表运行进程已经加载。重启、热加载和游戏内验证要单独记录，不能把静态检查写成已通过实机验证。
- 并行工作的宠物文件、账号数据库、角色存档及客户端可执行文件不属于本次修改范围。
- 不覆盖既有地图或整份混合编码数据表。新增和修复采用限定到目标记录的修改；遇到来源冲突先保留证据。
- 7.1 是本次目标版本。文件名后缀、素材编号或安装包版本标签不能单独证明一项内容在 7.1 已正式开放。

## 本轮交付

先建立实际可运行的盘点工具、可检查的差异报告和来源清单，再实施本地证据充分的第一批修复或新增。后续任务逐项按上述阶段推进；缺少数据或引擎能力的项目明确写出阻碍与所需输入。用户已确认没有另外的 6.0 至 7.1 DATA 或地图包，因此继续从本地文件和可验证的公开来源补齐。
